# LLM operational protocol

The supported default is an explicit fixed-policy baseline. A baseline is labelled `baseline:<policy>` in the world state and `mode: baseline` in provenance; it never calls a provider. No model capability ladder is assumed from parameter counts or marketing names.

Live mode requires explicit enablement, an exact model allowlist, credentials, and authenticated API requests. A species receives its own traits, filtered observation, visible resource definitions, and visible species identifiers. `promptBuilder.ts` is the versioned experimental prompt. An action is a bounded JSON decision; invalid live responses abort the run. The live parser requires finite in-range harvest/governance numbers, exact observed resource/species IDs, allowed relation/intent values and bounded messages. Unknown fields, invalid self/hidden targets and unsupported treaty constraints are rejected. Optional treaty proposals can be omitted or null. JSON code fences may be removed, but invalid actions are never clamped or silently substituted. There is no fallback mock, alternate provider, retry, or claim that an unexecuted model succeeded.

A call has a 30-second timeout and requests at most 1,000 generated tokens by default (at most 2,000 when using the internal adapter explicitly). Runs are bounded before any call; batch mode is baseline-only. The adapter targets the OpenAI chat-completion interface. `EVOLSIM_TOKEN_LIMIT_FIELD` accepts `max_completion_tokens` (default) or `max_tokens` for compatible local servers such as Ollama; any other value is rejected. `OPENAI_BASE_URL` is a server-side setting recognized by the SDK. Compatibility and enforcement by a particular provider must be tested explicitly before a study; a configured name is not evidence of compatibility or a completed evaluation.

There is no training or persistent cross-run learning. The observation may include recent events and active treaties within a run; describing the policy as having no memory would be inaccurate. A fixed environmental seed does not make remote model inference deterministic.

Protocol 2.1.1 filters event history, memory summaries and resource-tagged living similes through the same visibility boundary as current observations. Treaty checks use the proposer's visible resource set and references; hidden quantities are not exposed through rejection messages. Browser requests to the API also require the application's own origin, independently of bearer-token validation.

A publishable model-comparison experiment additionally needs an archived prompt/action transcript, resolved provider model version, sampling settings, token usage and cost, failed-attempt accounting, repeated samples per seed, and paired confidence intervals. The local compatibility runner records a bounded diagnostic and its failures; it does not supply repeated sampling or a powered model-comparison study. It uses local computation and records default sampling as unspecified rather than claiming environmental seeds control inference.

The October 14, 2026 local diagnostic returned four HTTP completions from Qwen2.5-Coder 0.5B Q4_K_M. Under the earlier parser, one of two one-step attempts appeared to complete. Inspection exposed invented identifiers and numeric repairs; the strict parser introduced in protocol 2.1.0 rejects all four retained responses during offline replay. The earlier completion is invalidated and is not evidence of cooperation. The [machine-readable summary](../results/local-validation-summary.json) separates original execution, per-call finish reasons and token usage, and offline replay.

Subsequent frozen pilots retained the strict semantics. The [interface experiment](INTERFACE_PILOT.md) obtained 7/8 valid grounded decisions versus 0/8 original decisions. The [episode experiment](EPISODE_PILOT.md), using protocol 2.2.0's optional schema and sampling controls, completed both four-step grounded runs while original runs stopped at zero steps. Both completed runs collapsed the resource at step 1. Raw requests/responses, partial histories, model/source hashes and descriptive summaries are archived under `results/`. These are bounded functional results, with unverified full-prompt context completeness; they do not support sustainability or a population-level strategy claim.

Protocol 2.3.0's optional `includeNumericRules` explains numerical resource transitions without exposing hidden stock. It is not a validated comprehension intervention. The separate `useIndependentRandomStreams` option isolates keyed exogenous draws from speech/treaty administrative draws. Both default off and require a new frozen experiment before their effects can be claimed.
